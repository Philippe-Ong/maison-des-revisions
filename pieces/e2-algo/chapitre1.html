À retenir

Comment utiliser cette fiche

Chaque section suit le même ordre : la notion (diapo), le code (extrait compilé et testé, numéro d'exercice entre parenthèses) et le piège. Les valeurs chiffrées sortent du script de contrôle. À relire la veille du TE : la méthode (§ 9), le mémo des pièges (§ 10) et l'auto-test (§ 11).
Intuition

L'idée directrice en une phrase

Un algorithme transforme une entrée en sortie par une suite finie et non ambiguë d'opérations (séquence, décision, répétition) ; sa complexité dit comment son coût grandit avec la taille N des données ; le C fournit les briques (types, structures, pointeurs = adresses) et la récursion ramène un problème à des cas plus petits, jusqu'au cas trivial.

1

Algorithme : définition, critères et démarche

Définition : une suite finie et non ambiguë d'opérations qui résout un problème ou donne un résultat ; en temps fini, d'une précondition (situation de départ) à une postcondition (résultat attendu). Le mot vient du mathématicien persan al-Khwarizmi (vers 780). Un algorithme est indépendant du langage : l'énoncé fixe la relation entrée \to sortie (« Input \to Data Manipulation \to Output » ; ex. trier 7, 5, 9, 6, 2, 1 en 1, 2, 5, 6, 7, 9).
Critères indispensables : des valeurs d'entrée et de sortie ; il se termine ; il est déterministe (fiable). Souhaités : efficace (durée déterminable), simple et compréhensible, maintenable, modulaire, flexible, convivial, robuste.
Démarche : analyser la fonctionnalité \to la décomposer « sur papier » (organigramme) \to planifier l'implémentation.
Trois constructions suffisent : séquence (instructions à la suite), décision (if, if-else, switch, ?:), répétition (do-while : test après, au moins un passage ; while / for : test avant, zéro passage possible).
#include <stddef.h>
#include <stdint.h>

/* « Find Largest value » (diapos 9-12), n >= 1 */
int32_t findLargest(int32_t const table[], size_t n)
{
    int32_t largest = table[0];      /* 1 : 1re valeur */
    for (size_t i = 1u; i < n; i++) {   /* répétition */
        if (table[i] > largest) {       /* décision */
            largest = table[i];         /* mise à jour */
        }
    }
    return largest;                     /* sortie */
}

Déroulé sur 7, 5, 9, 6, 1 : 7, 7, 9, 9, 9 \Rightarrow 9. Initialiser à la 1re valeur, pas à 0 : sinon {-4, -2, -7} rendrait 0 au lieu de -2 (testé). « Potentiel d'optimisation ? » (diapo 12) : chaque valeur doit être lue au moins une fois, on reste en O(n) ; on évite seulement de relire la 1re (boucle dès i = 1).

2

Complexité : coût en temps et en mémoire

Deux questions : calculabilité (existe-t-il un algorithme ?) et complexité (quel est le meilleur, à quel coût ?). Thèse de Church–Turing : une fonction est calculable par algorithme si et seulement si une machine de Turing la calcule.
Machine de Turing : bande infinie de cases (symboles d'un alphabet), tête de lecture / écriture qui se déplace d'une case, registre d'état, table de transitions (selon état et symbole lu : écrire ou non, bouger à gauche / à droite / rester, changer d'état).
Coûts : le temps (nombre de transitions) et la mémoire (nombre de cases utilisées). Ils dépendent de la taille N des données : trier 10 nombres \neq trier 1 000 000.

Formule
c=f(N)\qquad\text{(coût en temps } c_t \text{ ou en mémoire } c_s\text{)}

Exemple 1 (somme d'un tableau), toutes les instructions coûtent t : s := 0 une fois, puis N tours de 4 instructions (incrément du compteur, accès au tableau, addition, affectation).

Formule
c_t(N)=t+4N\,t=(1+4N)\,t\qquad c_t(10)=41\,t

Indépendant de l'ordre des nombres. Mémoire (proposé) : c_s(N)=N+2 cases (tableau, s, i).

Piège

Trois cases fausses dans la diapo 9

La colonne « \log_2 n » des lignes 10 et 20 est calculée avec \ln : 2,3 et 3,0 µs au lieu de 3,3 et 4,3 µs (idem n\log_2 n : 23 et 60 au lieu de 33 et 86 µs). Et 2^{60} µs =365 siècles, pas 266. Les conclusions ne changent pas : au-delà de n^3, la machine ne sauve rien.

Exemple 2 (diapo 13) = le tri à bulles de l'ex. 1.5. La diapo pose la question sans corrigé ; voici une convention proposée, au même grain que l'exemple 1 : s := 0 et le test until coûtent t chacun ; chaque tour de boucle coûte 4t (incrément, deux accès, comparaison) ; chaque échange coûte 3t (hypothèse de la diapo) +\,2t pour s := s+1. Avec P passes et I permutations :

Formule
c_t=P\,(4N-2)\,t+5\,I\,t\qquad \text{trié : }(4N-2)\,t=O(N)\qquad\text{ordre inverse : }\frac{N(13N-9)}{2}\,t=O(N^2)

Pour N=10 : 38 t (trié) contre 605 t (inverse). Les constantes dépendent de la convention, pas l'ordre de grandeur. Formules vérifiées par simulation (tous les N de 2 à 8, tirages aléatoires à graine fixe).

3

Langage C : de la source à l'exécutable, types et expressions

Programme : commentaires, directives (#include <stdio.h>), variables globales, fonction main (nom obligatoire ; int main(void) ou int main(int argc, char *argv[])), return 0;. Fichiers .c (code) et .h (types et prototypes publics).
Constantes : entières 27, 0x1A (hexa), 032 (octal !) ; caractère 'A', '\n', '\0' ; flottante 45.87e-2 (le point est obligatoire) ; chaîne "abc" = 4 octets (le compilateur ajoute '\0'). Les constantes binaires 0b1010 de la diapo sont une extension de gcc (standard seulement en C23 : -pedantic avertit).
Constantes symboliques : #define MAX (0x7fff) (substitution de texte : parenthéser !) ou enum { eBLEU, eJAUNE = 10, eVERT, eROUGE = 30, eBLANC }; \to 0, 10, 11, 30, 31 (la numérotation reprend à la dernière valeur imposée). Variable en lecture seule : uint16_t const cNbr = 10;.
Conversions : implicites dans une expression (char, short \to int ; int avec double \to double) ; explicites par cast (type)x. typedef crée un nom de type (portabilité : <stdint.h>).

Piège

Expression 6 : comportement indéfini

k = k++ + ++j; modifie k deux fois sans point de séquence : la norme C ne fixe pas le résultat (gcc -Wall avertit « operation on 'k' may be undefined »). La sortie de l'énoncé (k=12, j=7) n'est qu'un résultat possible : ne jamais écrire une telle ligne.
#include <stdbool.h>

/* Ex. 1.3 / 1.4 b) : 'a' = 0x61, 'A' = 0x41 (bit 5 = 0x20) */
char toUpperAscii(char c)
{
    if ((c >= 'a') && (c <= 'z')) {
        c &= ~0x20;      /* ET avec ~masque : efface le bit 5 */
    }
    return c;
}

/* Ex. 1.4 d) : ternaire  condition ? siVrai : siFaux */
char const *boolText(bool value)
{
    return value ? "true" : "false";
}
Ex. 1.4 avec cVarA = 12 (1100) et cVarB = 10 (1010) : 12|10 =14 (1110), 12&10 =8 (1000), 12^10 =6 (0110), ~12 =-13 (complément à 1 d'un int signé : -x-1).
Logique : toute valeur non nulle est vraie : 12 || 10 et 12 && 10 valent 1, !(12 == 10) aussi.
Majuscule (Ex. 1.3 et 1.4 b) : en ASCII, 'a' = 0x61 et 'A' = 0x41 ne diffèrent que par le bit 5 (0x20) ; c &= ~0x20 l'efface. On teste d'abord 'a' <= c <= 'z' (en C : (c >= 'a') && (c <= 'z')), sinon on abîmerait les chiffres et la ponctuation.
4

Structures de contrôle et fonctions

Boucles : do {...} while (cond); s'exécute au moins une fois (copie de chaîne jusqu'au '\0') ; while (cond) {...} teste d'abord ; for (init; cond; pas) {...} regroupe les trois (variable déclarée dans init depuis C99). Toujours modifier dans le corps ce que teste la condition. Boucle sans fin : while (1) ou for (;;) (programme principal d'un système embarqué, reset par watchdog).
Conditions : if-else ; switch (expr) { case CONST: ... break; default: ... } compare à des constantes entières ; sans break, l'exécution « tombe » dans le case suivant (à commenter : // Fall through). Sauts : break, continue (goto à éviter).
Fonctions : la déclaration (prototype, signature) int add(int, int); suffit au compilateur ; la définition contient le corps. Trois façons : prototype avant main et corps après ; corps avant main ; prototype dans un .h protégé par #ifndef X_H / #define X_H / #endif et corps dans un .c. void f(void) = procédure ; static devant une fonction la rend privée au fichier.
Passer l'information : variables globales (facile, mais effets de bord) ; arguments par valeur (copie) + return ; résultat par référence via un pointeur (void addAndModulo2(uint32_t a, uint32_t b, uint32_t *pResult), appel avec &resultOp4).
/* Ex. 1.6 : passage par valeur, résultat par return */
double celsiusToFahrenheit(double celsius)
{
    return celsius * 1.8 + 32.0;
}

/* Diapo « Fonctions (V) » : x et y sont des COPIES */
void swapByValue(int x, int y)
{
    int const tmp = x;
    x = y;
    y = tmp;               /* l'appelant ne voit rien */
}

/* Passage « by reference » : on reçoit les ADRESSES */
void swapByReference(int *pX, int *pY)
{
    int const tmp = *pX;
    *pX = *pY;
    *pY = tmp;             /* l'appelant voit l'échange */
}

/* static local : garde sa valeur entre les appels */
int getCount(void)
{
    static int count = 0;  /* initialisée une seule fois */
    count++;
    return count;
}
Variables : [classe] TYPE [qualificatif] nom [= init];. Classes : auto (défaut), static (globale : visible dans le seul fichier ; locale : garde sa valeur entre les appels), extern (définie dans un autre fichier, résolue à l'édition de liens), register. Qualificatifs : const (lecture seule), volatile (peut changer hors du programme : interruption, registre).
Déclaration (type et nom) \neq définition (réserve la mémoire, peut initialiser) \neq affectation (dans le code). Une variable locale non initialisée contient n'importe quoi.
Portée, du plus large au plus étroit : programme, fichier (static), fonction, bloc (C99). Une variable d'un bloc intérieur masque celle du bloc extérieur de même nom.

Ex. 1.6 — convertisseur : une fonction par tâche, des constantes pour les bornes.

Formule
T_\mathrm{F}=1{,}8\;T_\mathrm{C}+32\qquad(T_\mathrm{F}\text{ en °F},\ T_\mathrm{C}\text{ en °C})

De -20 à 30 °C par pas de 1 : 51 lignes ; -20\to-4{,}0, -19\to-2{,}2, 10\to50{,}0, 29\to84{,}2, 30\to86{,}0 °F (et -40 °C =-40 °F). La sortie de l'énoncé (+29.0) correspond au format %+.1f. Sur la console Windows, le symbole ° s'obtient avec le code 0xF8 (248).
Échange : swapByValue(x, y) ne change rien chez l'appelant (diapo « Fonctionne ? » : non) ; swapByReference(&x, &y) échange bien 13 et 15.

5

Tableaux, structures, unions (Ex. 1.7, 1.8)

Tableau : éléments d'un même type, contigus. int32_t t[] = {1, 3, 5}; ; indices de 0 à n-1 ; le C ne contrôle pas les bornes. Nombre d'éléments sans le noter en dur : sizeof t / sizeof t[0]. 2D : int32_t m[4][2] ; tableau de chaînes : char const cFruits[][NameLen] = {"orange", ...}. Le nom du tableau est l'adresse de son 1er élément.
Structure : regroupe des données liées, de types différents ; typedef struct {...} Student_t; (recommandé) ; accès s.membre, imbriqué s.homeAddress.city ; initialisation {"Linus", "Torvalds", eClass_E1a, {...}} ; l'affectation a = b; copie tous les champs (tableaux internes compris). Champ de bits : uint8_t P1OUT0 : 1; donne accès à un bit d'un registre (ordre des bits dépendant du compilateur).
Union : tous les membres partagent la même mémoire ; taille = celle du plus grand. Usages : une donnée de type variable dans le temps, conversion de type, registre vu en 16 bits ou en deux octets (PAOUT du MSP430).

Ex. 1.7 — struct tm (<time.h>) : tm_mon de 0 à 11 (+1 à l'affichage), tm_year compté depuis 1900 (+1900), tm_wday de 0 = dimanche à 6, tm_yday de 0 à 365. time(NULL) rend le temps courant (secondes depuis 1970) ; localtime(&t) rend un pointeur vers une struct tm interne, d'où *localtime(&t).
Ex. 1.7 b) — dépassement d'un time_t 32 bits signé : 2^{31}-1=2\,147\,483\,647 s (INT_MAX de <limits.h>) après le 1.1.1970 :

Formule
\mathrm{19.01.2038\ \ 03{:}14{:}07\ UTC}=\mathrm{04{:}14{:}07}\ \text{à Fribourg (un mardi)}

Sur ce PC (gcc MinGW, UCRT), time_t fait 64 bits : le problème « Y2038 » touche les time_t 32 bits (embarqué, anciens systèmes).
Piège de la note 1.7 : DATE_FORMAT commence par %02d ; pour afficher le texte devant, écrire "%s" DATE_FORMAT (concaténation de littéraux), jamais passer un char * à un %d.

#include <limits.h>
#include <stdio.h>
#include <time.h>

#define DATE_FORMAT "%02d.%02d.%04d %02d:%02d:%02d"

/* Ex. 1.7 c) : texte + struct tm passée par valeur (copie) */
void showTime(char const *text, struct tm t)
{
    printf("%s" DATE_FORMAT "\n", text, t.tm_mday, t.tm_mon + 1,
           t.tm_year + 1900, t.tm_hour, t.tm_min, t.tm_sec);
}

/* d) tm_wday (0 = dimanche) -> nom du jour ;
      static : le tableau survit au return */
char const *weekDayName(int weekDay)
{
    static char const *const cNames[] = {"Sunday",
        "Monday", "Tuesday", "Wednesday", "Thursday",
        "Friday", "Saturday"};
    if (weekDay < 0 || weekDay > 6) {
        return "?";                          /* hors table */
    }
    return cNames[weekDay];
}

/* b) dernière seconde d'un time_t 32 bits signé :
      INT_MAX = 2^31 - 1 */
struct tm lastSecondOfTime32(void)
{
    time_t const cMax = (time_t)INT_MAX;
    return *localtime(&cMax);   /* localtime rend un POINTEUR */
}

Ex. 1.8 — gestion d'adresses : structure imbriquée, enum pour la classe, typedef de chaînes, tableau de 30 étudiants mis à zéro par memset(studentsGE, 0, sizeof studentsGE), ajout, tri à bulles sur le nom de famille (§ 8). Résultat trié (testé) : Bykov, Lüthi, Sauber, Stallman, Torvalds, Wawrinka.

#include <stdbool.h>
#include <stddef.h>
#include <stdio.h>
#include <string.h>

/* Ex. 1.8 : constantes et types (diapo « Structures (I) ») */
enum { eNameLen = 20, eAddressLen = 40, eMaxStudents = 30 };
typedef char Name_t[eNameLen];
typedef char AddressName_t[eAddressLen];
typedef enum { eClass_E1a, eClass_E1bd, eClass_E2a,
    eClass_E2bd, eClass_E3_EL, eClass_E3_EN } Class_t;

typedef struct {
    AddressName_t street;
    int houseNbr;
    int zipCode;
    AddressName_t city;
} Address_t;

typedef struct {
    Name_t firstName;
    Name_t lastName;
    Class_t currentClass;
    Address_t homeAddress;          /* structure imbriquée */
} Student_t;
/* c) affichage de tout le tableau, message si vide */
void printStudents(Student_t const table[], size_t count)
{
    static char const *const cClass[] = {"E-1a", "E-1bd",
        "E-2a", "E-2bd", "E-3EL", "E-3EN"};
    if (count == 0u) {
        printf("No student in table available yet!\n");
        return;
    }
    for (size_t i = 0u; i < count; i++) {
        Student_t const *const pS = &table[i];
        Address_t const *const pA = &pS->homeAddress;
        printf("%u : %s %s, %s, %s %d, %d-%s\n", (unsigned)i,
               pS->firstName, pS->lastName,
               cClass[pS->currentClass], pA->street,
               pA->houseNbr, pA->zipCode, pA->city);

Pointeurs (Ex. 1.11)

Définition : un pointeur est une variable qui contient l'adresse d'une donnée (variable, structure, fonction…). Usages : rendre des résultats depuis une fonction, créer des objets dynamiques, accéder aux registres matériels. Déclaration : TYPE *pVariable;.
Adresse : pVar = &var1;. Déréférenciation : *pVar = 'B'; écrit dans var1. Il faut lui donner une adresse valide avant : déréférencer NULL ou un pointeur non initialisé est un comportement indéfini (plantage).
Structure : pPoint->x \equiv (*pPoint).x (les parenthèses sont nécessaires : . passe avant *).
Tableaux : ptbl = tbl; \equiv ptbl = &tbl[0]; ; p + 1 avance de sizeof(*p) octets : avec uint16_t a[4] en 0x3C6, a + 1 vaut 0x3C8 ; a[i] \equiv *(a + i).
Pointeur void * : générique ; le convertir avant de le déréférencer : *((char *)pVar).
Appel (diapo 11)Effet chez l'appelant
foo1(j), i = 2;j reste 1 (copie)
foo2(&j), *pi = 2;j vaut 2
foo3(ptr), pi = malloc(...)ptr reste NULL
foo4(&ptr), *ppi = malloc(...)ptr reçoit l'adresse

Pour modifier un pointeur de l'appelant : TYPE **pp.

/* d) côtés parallèles aux axes : coins 0 et 2 opposés */
void computeArea(Rectangle_t *pRect)
{
    int32_t const w = pRect->corners[2].x - pRect->corners[0].x;
    int32_t const h = pRect->corners[2].y - pRect->corners[0].y;
    pRect->area = (w < 0 ? -w : w) * (h < 0 ? -h : h);

{

Récursion (Ex. 1.2, 1.10, 1.14)

Définition : une fonction est récursive si elle s'appelle elle-même, directement ou par une suite d'appels (func1 \to func2 \to … \to func1). Une condition d'arrêt est indispensable : sans elle, la pile déborde (« stack overflow »).
Quand l'utiliser : un ou plusieurs cas simples ont une solution triviale, et les autres se reformulent en problèmes plus proches de ces cas. Schéma : if simpleCase solve else reformulate using recursion.
Diviser pour régner : un problème de taille n se découpe en un problème de taille 1 et un de taille n-1 (ou en deux moitiés), jusqu'au cas simple.
Exemples de la diapo : n!=n\cdot(n-1)! avec 0!=1 ; Fibonacci f(n)=f(n-1)+f(n-2), f(1)=f(2)=1 ; algorithmes de tri ; multiplication par additions : mult(n, m) rend m si n=1, sinon m + mult(n-1, m). Pile : mult(3,5) \to mult(2,5) \to mult(1,5) rend 5, puis 5+5, puis 5+10=15.
#include <stdint.h>

/* Ex. 1.2 a) itération */
uint64_t factorialIteration(uint32_t n)
{
    uint64_t result = 1u;
    for (uint32_t i = 2u; i <= n; i++) {
        result *= i;
    }
    return result;
}

/* b) récursion : n! = n * (n-1)! */
uint64_t factorialRecursion(uint32_t n)
{
    if (n <= 1u) {
        return 1u;          /* cas de base : 0! = 1! = 1 */
    }
    return n * factorialRecursion(n - 1u);
}

/* Ex. 1.10 : pseudo-code de l'énoncé ; *pMoves compte */
void toh(uint32_t disk, char source, char dest, char aux,
         uint32_t *pMoves)
{
    if (disk == 1u) {                          /* cas simple */
        moveDisk(1u, source, dest, pMoves);
    } else {
        toh(disk - 1u, source, aux, dest, pMoves); /* -> aux */
        moveDisk(disk, source, dest, pMoves);    /* le grand */
        toh(disk - 1u, aux, dest, source, pMoves); /* -> dest */
    }
}

Règles : un seul disque à la fois, jamais un grand sur un petit. Déplacer n disques = déplacer n-1 disques sur l'aiguille auxiliaire, le plus grand sur la destination, puis les n-1 par-dessus.

Formule
M(n)=2\,M(n-1)+1,\quad M(1)=1\quad\Rightarrow\quad M(n)=2^n-1

b) Le compteur passe par pointeur (uint32_t *pMoves) : pas de variable globale.

Arbre d'appels de toh(3, 'A', 'B', 'C') : les numéros donnent l'ordre des 7 déplacements, identique à la sortie de l'énoncé (« Move disk 1 from A to B », …). 64 disques : 2^{64}-1=18\,446\,744\,073\,709\, 551\,615 coups, soit 3{,}5\cdot10^{13} ans à 1 coup par minute, 5{,}8\cdot10^{8} ans à 1000 coups/s et encore 585 ans à 10^9 coups/s.

Tri à bulles (Ex. 1.5, réutilisé en 1.8 et 1.11)

#include <stddef.h>
#include <stdint.h>

/* Ex. 1.5 : pseudo-code de l'énoncé (repeat ... until s = 0).
   Renvoie le nombre total de permutations. */
uint32_t bubbleSort(int16_t table[], size_t n)
{
    uint32_t permutations = 0u;
    uint32_t s;
    do {
        s = 0u;                              /* s := 0 */
        /* for i = 2 to N  (indices C : 1 à n-1) */
        for (size_t i = 1u; i < n; i++) {
            if (table[i] < table[i - 1u]) {
                int16_t const tmp = table[i];  /* swap : 3 t */
                table[i] = table[i - 1u];
                table[i - 1u] = tmp;
                s++;                         /* s := s + 1 */
            }
        }
        permutations += s;
    } while (s != 0u);                       /* until s = 0 */
    return permutations;
}

Principe : on compare chaque paire voisine et on l'échange si elle est dans le mauvais ordre ; chaque passe pousse le plus grand restant en fin de tableau ; on s'arrête après une passe sans échange (s = 0).
Nombre de permutations = nombre d'inversions (paires i<j avec t_i>t_j) : chaque échange de voisins en corrige exactement une.

Séquence (10 nombres)Permut.Passes
énoncé : 28 3 45 1 5 17 33 32 42 2209

Un petit élément en fin de tableau ne recule que d'une case par passe (« tortue ») ; un grand au début traverse tout en une passe (« lièvre »). Complexité : O(n^2) dans le pire cas, O(n) si déjà trié (grâce au test s = 0).

Généraliser (Ex. 1.8 et 1.11) : on garde la boucle, on change le critère (strcmp(...) < 0 pour un nom, .area pour une surface) et l'échange copie la structure entière ; le critère peut même être passé en pointeur de fonction.
