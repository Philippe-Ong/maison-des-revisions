Algo 1.2 — Le factoriel d'un nombre (n!)

✦

Concept de base

Le factoriel d'un nombre entier naturel n (noté n!) est le produit de tous les entiers de 1 à n :

n! = 1 × 2 × 3 × … × n

Deux conventions incontournables :

0! = 1      (par définition)
1! = 1

L'exercice demande d'implémenter trois algorithmes différents pour calculer le même résultat, de 0 à 20. L'idée n'est pas seulement d'obtenir le nombre, mais de comparer trois façons de coder un algorithme :

Partie Technique Fonction
a) Itération (boucle for) Factorial_with_iteration()
b) Récursion (la fonction s'appelle elle-même) Factorial_with_recursion()
c) Table de valeurs calculée par le préprocesseur (LUT) Factorial_with_lut()
À retenir

LUT = Look-Up Table (« table de consultation »). Au lieu de calculer le résultat à chaque appel, on le range à l'avance dans un tableau et on le récupère instantanément par son index.

✦

Types entiers : pourquoi uint32_t, uint64_t, %llu

Le factoriel grandit très vite : 20! = 2 432 702 008 176 640 000. Cela dépassé la capacité d'un int (≈ 2 milliards). On utilise donc des types sans signe et larges, venus de <stdint.h> :

Type Taille Valeur max
uint32_t 32 bits (4 octets) 4 294 967 296
uint64_t 64 bits (8 octets) 18 446 744 073 709 551 615
  • uint32_t number → le paramètre (le n, de 0 à 20).
  • uint64_t → le résultat (peut être énorme).
  • %llu → le format printf pour un unsigned long long (≈ uint64_t) : « l » = long, « ll » = long long.
À retenir

À retenir : le numéro n tient dans un uint32_t, mais le résultat doit être un uint64_t sinon il déborderait (overflow). Le %u sert à afficher le uint32_t, le %llu au résultat uint64_t.

✦

a) Itération — la boucle for

On calcule le factoriel pas à pas avec une variable qui s'accroît à chaque tour de boucle :

uint64_t Factorial_with_iteration(uint32_t number)
{
    uint64_t result = 1;          /* produit de départ = 1 */
    if (number >= 2) {            /* 0! et 1! = 1, pas besoin de boucle */
        for (uint32_t i = number; i >= 2; i--) {
            result *= (uint64_t)i; /* result = result * i */
        }
    }
    return result;
}
  • On initialise result à 1.
  • La boucle descend de number jusqu'à 2 (i--).
  • À chaque tour, on multiplie result par i.
  • Le (uint64_t)i force la multiplication en 64 bits (au cas où i serait sur 32 bits).
À retenir

Pourquoi if (number >= 2) ? Parce que 0! et 1! valent 1. Sans ce filtre, la boucle ne ferait rien de toute façon, mais le if l'évite explicitement et rend le cas trivial clair.

Déroulé pour 3! : result=1 → ×3=3 → ×2=6 → retourne 6. ✓

✦

b) Récursion — la fonction s'appelle elle-même

Le factoriel a une définition récursive naturelle :

n! = n × (n-1)!      avec le cas de base 0! = 1

uint64_t Factorial_with_recursion(uint32_t number)
{
    if (number <= 1) {                 /* cas de base */
        return 1;
    }
    return number * Factorial_with_recursion(number - 1);  /* appel à soi-même */
}
  • Cas de base (number <= 1) : on renvoie 1 → c'est l'arrêt de la récursion, sinon la fonction appellerait à l'infini.
  • Cas récursif : on renvoie number × Factorial(number - 1).

Déroulé pour 3! (les appels se « empilent » puis se défilent) :

Factorial(3)
= 3  * Factorial(2)
      2  * Factorial(1)
            └─ retourne 1        ← cas de base
= 3 * (2 * 1) = 6
À retenir

À retenir : toute récursion a deux parties :

  1. un cas de base (ici number <= 1) qui arrête l'appel,
  2. une récursion qui récrit le problème plus petit (n! = n·(n-1)!). Sans cas de base → boucle infinie → plantage (stack overflow).
✦

c) LUT — la table de valeurs (préprocesseur)

Au lieu de calculer, on stocke tous les résultats dans un tableau static rempli à la compilation. On lit simplement l'index demandé :

static uint64_t const Fact[] = {
    (uint64_t)1,                    /* 0!  = 1        */
    (uint64_t)1,                    /* 1!  = 1        */
    (uint64_t)1*2,                 /* 2!  = 2        */
    (uint64_t)1*2*3,               /* 3!  = 6        */
    ...                            /* ...            */
    (uint64_t)1*2*3*...*20,        /* 20!             */
};

uint64_t Factorial_with_lut(uint32_t number)
{
    if (number >= sizeof(Fact) / sizeof(Fact[0])) {  /* hors limites */
        return 0;
    }
    return Fact[number];        /* lecture instantanée */
}
  • Le tableau Fact[] contient 21 valeurs (de 0! à 20!).
  • Fact[number] renvoie directement le résultat : O(1), aucune calcul.
  • Les (uint64_t) forcent le calcul à la compilation (le préprocesseur / le compilateur évalue 1*2*3*… une fois pour toutes).

sizeof(Fact) / sizeof(Fact[0])

Cette formule donne le nombre d'éléments du tableau, sans le noter en dur :

sizeof(Fact)        /* taille totale du tableau en octets */
sizeof(Fact[0])     /* taille d'un seul élément (1 uint64_t = 8 octets) */
sizeof(Fact)/sizeof(Fact[0])   /* = nombre d'éléments = 21 */
À retenir

Pourquoi cette condition ? Le tableau ne contient que 0..20. Si on demande 21 ou plus, on sortirait des limites du tableau (lecture d'une mémoire invalide). On renvoie 0 pour signaler « hors plage ». En vrai, 21! dépasse déjà un uint64_t → 0 = message d'erreur honnête.

À retenir

static + const : le tableau est créé une seule fois, stocké en mémoire et non modifiable. Il existe pendant toute la vie du programme.

✦

main() : les trois boucles

main() parcourt i de 0 à 20 et affiche le résultat des trois fonctions :

for (uint32_t i = 0; i <= 20; i++) {
    uint64_t const cResult = Factorial_with_iteration(i);
    printf("The factorial of %u using loop is: %llu\n", i, cResult);
}
/* idem avec Factorial_with_recursion(...) et Factorial_with_lut(...) */
  • uint32_t i : compteur de 0 à 20.
  • uint64_t const cResult : le résultat est constant (on ne le modifie pas après).
  • Boucle identique pour les trois fonctions : on compare donc à conditions égales.
✦

Sortie attendue (extraits)

The factorial of 0 using loop is: 1
The factorial of 1 using loop is: 1
The factorial of 2 using loop is: 2
The factorial of 3 using loop is: 6
...
The factorial of 20 using loop is: 2432902008176640000

Les trois méthodes produisent exactement les mêmes nombres (de 1 à 2 432 702 008 176 640 000 pour 20!), mais par des chemins différents.

✦

Comparaison des trois approches

Critère a) Itération b) Récursion c) LUT
Principe boucle for appel à soi-même tableau précalculé
Mémoire 1 variable pile d'appels 21 valeurs fixes
Vitesse rapide plus lente (empilement) instantanée (O(1))
Place au compile non non oui (constantes évaluées)
Limite jusqu'à overflow jusqu'à overflow bornée par le tableau
Lisible oui très proche de la définition compact
À retenir

Le choix en embarqué : la LUT est idéale quand l'ensemble des résultats est connu à l'avance et fini (comme 0..20!) : on paie une fois en place mémoire à la compilation, et à l'exécution c'est une simple lecture de tableau, rapide et prédictible — parfait pour un microcontrôleur.

✦
